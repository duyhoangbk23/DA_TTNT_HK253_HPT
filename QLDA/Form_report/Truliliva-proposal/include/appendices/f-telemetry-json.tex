\chapter{Đặc tả JSON và mapping telemetry}
\label{app:telemetry-json}

\section{Payload canonical}

Payload MQTT canonical có ba trường. Giá trị dưới đây chỉ là mẫu minh họa,
không phải định danh hay thông tin xác thực của môi trường:

\begin{verbatim}
{
  "mcu_id": "ESP32_001",
  "tds": 187,
  "alert": "normal"
}
\end{verbatim}

\begin{itemize}
  \item \texttt{mcu\_id}: chuỗi không rỗng, tối đa 50 ký tự;
  \item \texttt{tds}: số, nullable ở schema; simulator hiện sinh số nguyên;
  \item \texttt{alert}: chuỗi nullable; simulator sinh \texttt{normal} hoặc
  \texttt{warning} theo ngưỡng TDS trong source.
\end{itemize}

Simulator publish lên topic ghép từ \texttt{TOPIC\_PREFIX} và hậu tố
\path|/telemetry|. Tài liệu không sao chép hostname, username, password,
certificate hay giá trị secret từ file cấu hình (E-SIM-03--E-SIM-04).

\section{Envelope của Device Monitor}

Callback mqtt.js parse message, sau đó POST envelope sau vào Slim API:

\begin{verbatim}
{
  "topic": "devices/telemetry",
  "payload": {
    "mcu_id": "ESP32_001",
    "tds": 187,
    "alert": "normal"
  },
  "source": "hivemq-web"
}
\end{verbatim}

\texttt{TelemetryService::normalize} bóc các object lồng có tên
\texttt{payload}, \texttt{telemetry}, \texttt{data}, \texttt{message} hoặc
\texttt{reading}; nó chỉ nhận \texttt{mcu\_id} cho định danh canonical.
Timestamp trong payload không được giữ lại; service tạo thời gian UTC khi nhận.
Repository sau đó yêu cầu MCU ID là chuỗi không rỗng, tối đa 50 ký tự và ghi:

\begin{verbatim}
{
  "timestamp": "<UTC server time>",
  "topic": "devices/telemetry",
  "mcu_id": "ESP32_001",
  "tds": 187,
  "alert": "normal"
}
\end{verbatim}

Trường \texttt{source} chỉ nằm trong envelope và không được lưu
(E-DM-03--E-DM-06).

\section{API Admin}

\path|POST /api/telemetry| của Laravel nhận payload phẳng hoặc object
\texttt{payload} lồng. Validator yêu cầu \texttt{mcu\_id} là chuỗi tối đa 50 ký tự;
\texttt{topic}, \texttt{timestamp},
\texttt{tds}, \texttt{alert} là tùy chọn. Khi thiếu, topic dùng mặc định
và timestamp dùng thời gian server. Model \texttt{Telemetry} ghi thêm
\texttt{created\_at}/\texttt{updated\_at} theo hành vi Eloquent mặc định
(E-ADM-05, E-DB-02).

\section{Tính tương thích hiện tại}

\texttt{SimulatorConfig::MCU\_ID} là chuỗi và được gán trực tiếp vào payload.
Contract hiện tại của Device Monitor và migration telemetry cũng dùng \texttt{mcu\_id}
dạng chuỗi tối đa 50 ký tự. Live test đã xác nhận publish--persist thành công qua
HiveMQ và Device Monitor vào MySQL.
