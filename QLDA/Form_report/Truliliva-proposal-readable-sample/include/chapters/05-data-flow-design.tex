\section{Luồng telemetry chuẩn}

\input{include/diagrams/telemetry-sequence}

Luồng được suy ra trực tiếp từ source theo thứ tự sau:

\begin{enumerate}
  \item \path|SimulatorApp::loop| gọi publish theo chu kỳ; \texttt{publishTelemetry} dừng ngay nếu MQTT chưa kết nối, tạo TDS mẫu và cảnh báo theo ngưỡng trong code (E-SIM-02, E-SIM-03).
  \item \path|MqttManager::publishTelemetry| serialize JSON và publish lên topic \path|TOPIC_PREFIX/telemetry|; client TLS đang dùng chế độ không xác minh chứng thư (E-SIM-04).
  \item mqtt.js trong Device Monitor subscribe danh sách topic qua WSS. Khi nhận message, callback thử parse JSON rồi gửi \texttt{topic}, \texttt{payload}, \texttt{source} đến Slim \path|POST /api/telemetry| (E-DM-06).
  \item Route Slim yêu cầu \texttt{topic}, gọi \path|TelemetryService::normalize|; service luôn tạo timestamp UTC phía server và trích \path|mcu_id|, TDS, alert từ payload (E-DM-02, E-DM-03).
  \item \path|TelemetryRepository::insert| yêu cầu \path|mcu_id| là chuỗi không rỗng tối đa 50 ký tự, ghi \path|timestamp, topic, mcu_id, tds, alert|, sau đó đọc lại bản ghi vừa tạo (E-DM-04).
  \item Trang \path|devices.show| của Admin truy vấn telemetry liên quan đến MCU/product, sắp xếp theo timestamp và dựng đồ thị TDS/cảnh báo (\path|DeviceController::show|, \path|Device::telemetry|, \path|resources/views/devices/show.blade.php|).
\end{enumerate}

\section{Luồng lỗi có bằng chứng}

\input{include/diagrams/error-sequence}

Các phản hồi lỗi được giới hạn ở những nhánh tồn tại trong code:

\begin{itemize}
  \item Device Monitor không tạo client nếu thiếu broker URL hoặc port; sự kiện mqtt.js \texttt{error} và \texttt{close} cập nhật trạng thái kết nối trên giao diện (\path|app.js::connectToHiveMQ|, E-DM-06).
  \item Slim trả HTTP 422 khi thiếu topic, khi payload thiếu/không hợp lệ \path|mcu_id|, và trả HTTP 500 với thông báo tổng quát khi persistence ném lỗi khác; thông báo exception nội bộ không được trả ở nhánh 500 (\path|public/index.php|, \path|TelemetryRepository.php|, E-DM-02, E-DM-04).
  \item Client browser kiểm tra \path|response.ok|; lỗi POST được bắt và hiển thị dưới dạng ``Lỗi lưu telemetry'', còn lỗi tải danh sách được chuyển thành trạng thái không tải được dữ liệu (\path|public/assets/app.js|, E-DM-06).
  \item API Admin dùng Laravel validator yêu cầu \path|mcu_id| là chuỗi tối đa 50 ký tự; payload không đạt điều kiện đi theo phản hồi validation của framework. Source không định nghĩa retry hay dead-letter queue cho cổng này (\path|TelemetryController::ingest|, E-ADM-05).
  \item Worker .NET bỏ qua payload rỗng, JSON sai hoặc thiếu \path|device_id|; mất kết nối bất thường kích hoạt vòng reconnect cách quãng năm giây. Các nhánh này chỉ áp dụng cho schema legacy của worker (\path|MqttService.cs|, \path|DeviceService.cs|, E-MQ-03).
\end{itemize}

\section{Các đường dữ liệu song song}

API Laravel \path|POST /api/telemetry| có thể ghi trực tiếp vào bảng chuẩn sau khi xác nhận MCU tồn tại, nhưng không được gọi bởi code Device Monitor. Worker .NET cũng subscribe broker, song ghi \path|device_data| thay vì \texttt{telemetry}. Do đó kiến trúc có một đường chuẩn qua Device Monitor, một cổng Admin độc lập và một đường worker legacy; không gộp ba đường thành một luồng thành công duy nhất (E-DM-06, E-ADM-05, E-MQ-03--E-MQ-05).
